## 3. 一次点击的完整数据流

```
玩家点击屏幕
   │
   ▼
document click（交互层）── 弹窗/抽屉打开？→ 拦截或收起抽屉
   │
   ▼
advance()
   ├─ phase==="type"  → skipType()   补完当前句
   ├─ phase==="wait"  → waitResume() 进入下一句（或从 AUTO 切回手动）
   └─ phase==="done"  → go(cur.next) 进入下一节点
                        │
                        ▼
                go(id) → S.id=id; save(); renderNode(node)
                        │
                        ├─ 节点级 fx 结算（applyFx，仅一次）
                        ├─ 切 chat / avg 模式、换背景/BGM/立绘
                        └─ pumpChat / pumpAvg（逐句）
                              ├─ typewrite() 逐字打印（标点额外停顿）
                              └─ holdLine() 句末等待 → 点击/自动续播
                                    └─ 全部播完 → afterLines()
                                          ├─ 有 o → showChoices()（写选项，点击后 applyFx + go）
                                          ├─ 有 next → 显示「点击继续 ▼」
                                          └─ j==="branch" → 空気检查 → pickRoute() → 写路线选项
```

## 4. 状态机（phase）

播放循环不靠"阻塞"，而靠三相位 + 定时器令牌：

| 相位 | 含义 | 谁离开该相位 |
|------|------|-------------|
| `type` | 打字机运行中 | 打完 → `holdLine()`；点击 → `skipType()` |
| `wait` | 一句打完，等待推进 | 点击 → `curAdvance()`；自动模式 → `waitTimer` 超时 |
| `done` | 节点全部播完 | 点击 → `go(cur.next)`；或等待选项被点击 |

- **定时器令牌 `sess`**：`renderNode()` 每次 `++sess`，所有 `setTimeout` 回调先校验 `token!==sess` 即失效，避免"切节点后旧计时器把剧情推着走"。
- **`busy/typer/waitTimer/waitResume/curAdvance`**：分别表示"正在播","当前打字任务","自动播放计时器","等待期点击回调","推进下一句的函数"，由 `clearWait()` 统一回收。

## 5. 存档与回滚设计

| 键 | 内容 | 写入时机 |
|----|------|---------|
| `xqxq_gal_v1` | 完整状态 `S`（当前节点 id、羁绊 a、资质 s、flags f、节点级 fx 已结算表 fxDone、回收进度 unlocked、回滚点 cp、设置 se/bgm/trk） | `go()` 每次跳转、结算 fx、解锁结局、修改设置 |
| `xqxq_gal_pref` | 阅读偏好 `{auto,spd}` | 切换自动/速度时 |

- **回滚点 `cp`**：第一次进入第 7 日分岔（`pickRoute()`）时把当前 `S` 快照存入 `cp`。任意结局卡上出现「↪ 回到分岔之夜」按钮：`loadCP()` 还原存档，但**回收进度/设置/水群值不回滚**，用于刷多结局。
- **`fxDone`**：按节点 id 记录"节点级 fx 已生效"，防止读档重进同一节点重复加羁绊。

## 6. 两版架构对比（为什么以豆包版为底座）

| 维度 | v0.2（`group-chat-galgame.html`） | 豆包版 v1.0 / 完整版 |
|------|-----------------------------------|----------------------|
| 剧本结构 | 数组 `S`（185 行），节点间靠 `label`+`jump` 跳转，顺序即流程 | 对象 `NODES`（131 节点），显式 `next`/`o[].goto`，是真正的有向图 |
| 播放方式 | `async play()` + `await wait(ms)` 线性协程 | `phase` 状态机 + 定时器令牌，可暂停/跳过/自动 |
| 文本呈现 | `textContent` 一次写入 | `typewrite()` 打字机，标点独立停顿，可点击补完 |
| 阅读控制 | 仅有"快进"开关 | 手动/自动 × 慢/普/快三档（`SPEEDS`） |
| 存档 | 无（刷新即重开） | localStorage 自动存档 + 回滚点 |
| 结局系统 | `BEDATA` 9 + `ENDING` 7，只写"序章" | 18 BE + 15 GE（完整版扩到 23 BE），带回收室 |
| 好感展示 | 「群成员」抽屉（沦陷度进度条） | 顶栏资质统计（完整版把抽屉也移植了回来） |
| 复读彩蛋 | 有（水群值 + 禁言 BE-24） | 无（完整版移植） |
| 音频 | `BGM` IIFE 4 曲目 + `sfx` | `AU` 5 曲目×4 织体 + 6 音效 + 本地文件播放 |

结论：**豆包版在引擎能力上全面领先，v0.2 在"群氛围系统"（复读/水群/成员面板/反派支线）上更有味道**，因此完整版 = 豆包版引擎 + v0.2 机制的内容回迁 + 缺陷修复。详见 [07](./07-版本对比与v1.0合并说明.md)。
